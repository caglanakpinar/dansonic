# dansonic

Dansonic watches you move through a webcam and turns that into sound. Perform a
dance move it recognizes and it plays that move's sound — this is the main
workflow. There's also a simpler demo where a rising/falling hand continuously
controls a clip's playback speed, no specific move required.

The current implementation lives in `v0/`. **Run every command below from
inside `v0/`.**

## Setup

```bash
cd v0
poetry install
poetry shell
```

Needs a webcam.

## Project layout

- `v0/dansonic_move/` — a sketch per move (e.g. `ab.jpeg`), for humans to read
  ("what does 'ab' look like"). A move can have more than one keyframe sketch,
  e.g. `thin.jpeg` + `thin2.jpeg`.
- `v0/dansonic_sounds/` — the sound each move triggers, same filename stem as
  its sketch (`ab.jpeg` → `ab.mp3`). A move only exists if it has a sound file.
- `v0/dansonic_move/templates/` — recorded pose data per move, generated by
  the recorder below. This is what live matching actually compares against —
  the sketches can't be used directly (MediaPipe can't detect a person in a
  hand-drawn sketch).
- `v0/src/motion_capture/` — webcam capture, MediaPipe tracking, move matching.
- `v0/src/music/` — sound playback.
- `v0/examples/reference_clip.wav` — sample clip for the hand-raise demo.

**To add a new move**: drop in a sketch (`dansonic_move/newmove.jpeg`) and a
sound (`dansonic_sounds/newmove.mp3`) with matching names, then record its
template (step 1 below).

## Main workflow: move → sound

### 1. Record each move

```bash
poetry run python -m motion_capture.template_recorder --missing
```

Opens the camera and, for every move that doesn't have a template yet: counts
down, plays that move's sound as a timing cue, then records ~2 seconds of your
pose. One camera session covers all of them back to back.

Record specific moves instead of everything missing:

```bash
poetry run python -m motion_capture.template_recorder ab ab2 thin wha-been
```

Useful flags: `--seconds` (recording length, default 2.0), `--countdown`
(get-ready time, default 5.0), `--no-sound` (skip the cue), `--no-preview`.

### 2. Run live matching

```bash
poetry run python -m motion_capture.live_cli
```

Starts the camera; performing a recorded move plays its mapped sound.
Detection checks on a steady 1-second beat by default, so triggers land on a
grid rather than firing mid-motion — useful for keeping it in time with music.

Useful flags:

| Flag | Default | Meaning |
|---|---|---|
| `--tick` | `1.0` | Seconds between detection checks. `0` = check every frame instead. |
| `--max-distance` | `0.8` | How closely a pose must match a template to trigger. Lower = stricter. |
| `--cooldown` | `1.0` | Minimum seconds between repeat triggers of the *same* move. |
| `--camera` | `0` | Camera index. |
| `--no-preview` | off | Skip the preview window. |

Both commands share `--model-complexity` (`0`/`1`/`2`, default `0`, faster = `0`).
**Keep it the same on both** — templates and live matching need to use the
same MediaPipe model to compare correctly.

## Other demo: continuous hand-raise → pitch/speed

```bash
poetry run python -m motion_capture examples/reference_clip.wav
```

No specific move to learn — just raise or lower your hand and the clip's
playback speed (and pitch, turntable-style) follows live.

## Offline tool: split a video into motion/sound pairs

```bash
poetry run python -m motion_capture.pipeline path/to/dance_clip.mp4
```

Given a video of someone dancing to music, slices it into each rising-hand
figure paired with the slice of the video's own soundtrack that played under
it — a small dataset of "this motion sounds like this", written to
`src/motion_capture/output/`.

## Troubleshooting

**`Invalid version '...' on package ...` (e.g. `Invalid version 'analytics' on
package analytics`)** — this isn't a dansonic bug. It means `poetry run` was
executed outside `v0/`, so Poetry couldn't find `pyproject.toml`, fell back to
some other environment on your machine, and choked on unrelated, corrupted
package metadata there. Fix: `cd v0` before running any `poetry` command.

## Before pushing to GitHub

`.gitignore` currently excludes `*.mp3` and `*.wav`, which means
`dansonic_sounds/*.mp3` and `examples/reference_clip.wav` won't be committed
as they are. If you want the repo to work out of the box for anyone who
clones it, either commit those specific files explicitly or adjust
`.gitignore` before pushing.
